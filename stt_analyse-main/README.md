# Протокол видеовстречи

Бот принимает запись встречи в Telegram или из папки `data`, делает транскрипт с разделением говорящих через AssemblyAI и собирает протокол через OpenAI по правилам из `prompt.md`.

Подходят файлы `mp3`, `mp4` и `mkv`. Результат каждой обработки сохраняется в Postgres. Для файла из папки `data` рядом появляются транскрипт, протокол в Markdown и тот же протокол в docx.

## Запуск

1. Установите зависимости:

```bash
pip install -r requirements.txt
```

2. Создайте `.env` на основе `.env.example` и заполните ключи:

```env
TELEGRAM_BOT_TOKEN=...
ASSEMBLYAI_API_KEY=...
OPENAI_API_KEY=...
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=gpt-6-sol
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/tg_audit
DATA_DIR=data
```

3. Положите запись в `data` или запустите бота и отправьте файл в Telegram:

```bash
python bot.py
```

## Запуск через Docker Compose

1. Заполните `.env` (минимум `TELEGRAM_BOT_TOKEN`, `ASSEMBLYAI_API_KEY`, `OPENAI_API_KEY`).
2. Поднимите сервисы:

```bash
docker compose up --build
```

Это запустит:

- `bot` с приложением
- `db` (Postgres 16) с volume для данных

Каталог `data` смонтирован в `/app/data`. Файл, который уже лежит в папке на хосте, бот забирает сам. В Docker-сети бот использует `DATABASE_URL=postgresql://postgres:postgres@db:5432/tg_audit`. Значение `DATABASE_URL` из `.env` для контейнера игнорируется, чтобы не было ошибки с `localhost`.

## Как использовать

1. Положите `mp3`, `mp4` или `mkv` в `data`. Когда обработка закончится, рядом будут `<имя файла>.transcript.txt`, `<имя файла>.protocol.md` и `<имя файла>.protocol.docx`.
2. Либо откройте диалог с ботом, отправьте `/start` и тот же файл. В чат придёт текст протокола, файл docx и транскрипт.
3. Пока рядом с записью из `data` есть `.protocol.md`, распознавание второй раз не запускается. Если docx ещё нет, бот собирает его из этого markdown.

## Куда сохраняется результат

Запись из папки `data` остаётся в ней. Рядом бот пишет транскрипт и оба протокола. Эти файлы в git не входят.

Запись из Telegram бот забирает во временный каталог `tg_meeting_`. Оттуда в чат уходят `<имя>.transcript.txt` и `<имя>.protocol.docx`. После отправки каталог удаляется, исходный файл из чата на диск не копируется.

Текст транскрипта и текст протокола из обоих путей пишутся в PostgreSQL, таблица `video_audits`. Для файла из `data` поле `username` равно `data-folder`, а `chat_id` равен 0. Для файла из Telegram в строке chat id и username отправителя. Поле `analysis` хранит протокол.

## Протокол

`prompt.md` задаёт роль секретаря и обязательные разделы: шапка, председатель и секретарь, присутствующие, повестка, обсуждение, решения, поручения с ответственным и сроком, открытые вопросы, следующая встреча, материалы. Чего в записи не было, в протоколе так и написано.

## Важно

- Транскрипт делится на спикеров: AssemblyAI вызывается с `speaker_labels`, языком `ru` и моделями `universal-3-5-pro` и `universal-2`. Параметр `speech_model=best` из макета сервис больше не принимает.
- Для длинной записи обработка может занять несколько минут.
- Таблица `video_audits` создаётся при старте. В поле `analysis` лежит текст протокола.
- Если обработка файла из `data` упала, причина записана в `<имя файла>.error.txt`. После исправления этот файл нужно удалить, иначе повтор не начнётся.
